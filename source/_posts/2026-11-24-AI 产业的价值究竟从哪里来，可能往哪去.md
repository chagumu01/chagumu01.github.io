AI 行业似乎永远不缺新的技术概念。从早期的大语言模型、多模态，到后来的 RAG、Agent、MCP，再到如今的 Context Engineering、Harness Engineering，每隔一段时间，我们就需要重新理解一些技术，甚至重新审视之前的技术积累。

但如果将时间尺度拉长到未来五年、十年，我们是否能够找到一条相对稳定的产业发展主线？在不断变化的技术和产品形态背后，AI 产业究竟在创造什么价值？

我认为，从技术价值创造的角度来看，未来 AI 产业的发展大概率会围绕三个方向展开：

- **造大脑（Foundation Model）：** 创造更强大的智能，拓展机器的能力边界。
- **搭底座（Infra）：** 降低智能的生产与使用成本，让智能能够规模化运行。
- **让大脑干活（Agent）：** 将智能组织成能够自主完成实际工作的生产系统。

这三个方向分别对应智能的创造、供给和价值转化。未来可能还会出现大量新的技术概念，但其中相当一部分创新，最终都可以回归到这三个问题上。

沿着这条主线，我们可以进一步思考 AI 产业未来的技术演化、商业模式以及价值分配。

## **一、AI 产业的价值从哪里来**

### **1.1 基模创造智能的增量**

基础模型的核心价值在于拓展人类能够借助机器解决的问题范围。

过去，传统软件需要开发者提前定义业务逻辑，机器按照确定性的规则执行任务。这种方式能够很好地处理标准化问题，但面对开放性需求、复杂语义和未知环境时，往往需要大量人工参与。

大模型改变了这一点。通过自然语言理解、推理和泛化能力，机器开始具备处理非结构化问题的能力。

每一次模型能力的突破，都可能创造一批新的应用机会。代码能力的发展催生了 Coding Agent，多模态能力的发展扩大了 AI 在视觉交互中的应用范围，推理能力的增强则让更加复杂的任务规划和辅助决策成为可能。

因此，基模创造的是一种能力增量。它决定了哪些过去难以自动化的问题，现在有机会被机器解决。

### **1.2 Infra 创造智能的效率增量**

智能具备某项能力之后，还需要解决一个现实问题：使用这种能力是否划算？

假设一个模型能够独立完成一项复杂的软件开发任务，但执行过程中需要消耗大量算力，最终成本甚至超过人工开发，那么这种能力就很难被大规模应用。

Infra 的价值就在于解决智能从技术可行走向经济可行的过程。

从 GPU 算力、推理加速到模型量化，从 KV Cache 优化到模型路由，这些技术虽然处于不同的工程层面，但都在改善智能的供给效率。

我们可以类比电力的发展。发电技术创造了电能，而输电网络和配电系统让电能能够进入工厂、商业建筑和普通家庭。电力真正改变社会生产方式，依赖的是整套基础设施的成熟。

AI 也可能经历类似的过程。模型创造智能，Infra 让智能成为一种能够被广泛使用的生产资源。

### **1.3 Agent 创造智能的生产力增量**

模型能够理解问题和生成答案，但真实世界中的工作往往涉及更加复杂的执行过程。

以软件开发为例，完成一个需求，需要经历需求分析、任务拆解、代码修改、测试验证和最终交付。即使模型具备很强的代码生成能力，也需要外部工具、业务上下文和执行机制的配合。

Agent 的价值在于将这些能力组织起来，形成完整的任务执行系统。

从这个角度看，RAG、MCP、Skill、Memory 和 Harness Engineering 都可以理解为将智能转化为生产力的不同技术手段。

它们分别解决知识获取、外部连接、能力复用、经验积累和执行控制等问题，最终服务于同一个目标：让机器能够更加可靠地完成现实世界中的工作。

三个方向所创造的价值，可以归纳为以下结构。

| 产业方向         | 核心价值   | 解决的问题                   |
| ---------------- | ---------- | ---------------------------- |
| Foundation Model | 智能增量   | 机器能够做什么               |
| Infra            | 效率增量   | 机器能否低成本、规模化地工作 |
| Agent            | 生产力增量 | 机器能否完成实际工作         |

这三个问题也将长期影响 AI 产业的发展方向。

## **二、基模可能往哪里发展**

### **2.1 从回答问题走向解决问题**

未来基础模型的竞争，可能逐渐从知识覆盖和内容生成，转向复杂问题的解决能力。

过去，我们评价一个模型是否足够优秀，通常关注它能否回答专业问题、生成高质量内容以及理解复杂指令。但随着这些能力逐渐成熟，模型需要面对的将是更加开放和复杂的任务。

例如，未来的模型在面对一个陌生的软件项目时，需要自主理解项目架构，识别潜在问题，探索不同的解决方案，并根据执行反馈调整自己的判断。

这要求模型具备更强的长程推理、任务规划和环境理解能力。

进一步来看，模型未来需要解决的可能是如何在不确定的环境中，通过有限的信息和资源，持续推进一个目标的实现。

模型的评价标准也可能随之发生变化，从单轮回答质量逐渐扩展到复杂任务成功率、长期决策稳定性和未知环境中的适应能力。

### **2.2 模型将不断吸收应用层的能力**

未来模型能力的提升，很可能不断改变上层应用的技术架构。

我们现在开发 Agent 时，经常需要设计复杂的 Prompt、反思机制和任务编排流程。其中一部分工程设计，是为了弥补当前模型在规划、推理和工具使用方面的不足。

随着模型能力不断增强，这些机制可能逐渐被简化。

例如，今天开发一个研究型 Agent，可能需要手动设计信息检索、内容阅读、交叉验证和报告生成等环节。未来的模型可能具备更强的自主规划能力，能够根据研究目标自行决定如何组织这些步骤。

这种变化意味着，AI 应用层的技术壁垒始终处于动态变化之中。今天需要大量工程设计才能实现的功能，明天可能成为模型的原生能力。

因此，我们在选择技术方向时，需要思考一个问题：

**当前正在解决的问题，究竟源于模型暂时存在的能力缺陷，还是现实世界长期存在的需求？**

模型能力缺陷会随着技术发展不断变化，而业务权限、数据治理、任务状态和结果验证等问题，仍然需要系统工程层面的解决方案。

### **2.3 模型可能走向通用化与专业化并存**

未来基础模型的发展未必只存在一条追求通用智能的路线。

一方面，通用模型会继续拓展能力边界，追求更强的推理、泛化和跨领域任务处理能力。另一方面，专业模型可能围绕特定领域进行深度优化，以获得更好的执行效率和专业表现。

对于医疗、金融、工业等领域而言，企业需要考虑的不仅是模型是否聪明，还包括专业知识、响应速度、数据隐私和运行成本。

因此，未来的模型生态可能由少量高能力通用模型、大量专业模型以及不同规模的轻量化模型共同组成。

这也为下一层 Infra 的发展创造了新的空间。当模型种类越来越多，如何根据任务选择合适的智能资源，就会成为一个重要的基础设施问题。

## **三、Infra 可能往哪里发展**

### **3.1 智能可能逐渐成为一种通用资源**

未来 Infra 的一个重要发展方向，是将智能抽象为更加标准化、可调度的基础资源。

过去企业使用计算资源，需要自行采购服务器、部署应用和维护运行环境。随着云计算的发展，计算能力逐渐被抽象为可以按需获取的服务。

智能也可能经历类似的过程。

未来开发者在构建应用时，可能不需要为每一个业务场景绑定固定的模型，而是描述任务对智能资源的需求，由底层平台完成模型选择、资源分配和运行调度。

例如，简单的信息分类任务使用轻量化模型，复杂的推理任务使用高能力模型，涉及企业敏感数据的任务则使用私有化部署模型。

在这一过程中，Model Gateway、模型路由、统一推理平台和资源调度系统可能成为越来越重要的基础设施。

当智能供给逐渐标准化，应用开发者也可以将更多精力投入业务设计，而减少对底层模型差异的关注。

### **3.2 智能成本下降可能创造更大的市场**

Infra 的价值还体现在，它可能通过降低成本创造原本不存在的需求。

经济学中有一个值得关注的现象，叫作杰文斯悖论（Jevons Paradox）。当一种资源的使用效率提高、使用成本降低时，人们可能扩大对这种资源的使用范围，最终导致资源总消耗增加。

这一现象也可能出现在 AI 产业中。

假设过去一家企业因为模型调用成本较高，只会在重要版本发布前使用 AI 进行代码审查。随着推理成本下降，企业可能开始对每一次 PR 进行自动审查，甚至在开发过程中实时分析每一次代码修改。

单次调用的成本下降了，但调用频率和使用范围都在扩大。

未来，当智能足够便宜时，我们可能会在大量目前没有使用 AI 的场景中引入智能能力。例如，持续监控系统运行状态、自动维护内部知识库、实时分析业务异常。

因此，Infra 厂商的未来机会不仅来自现有智能需求的增长，也可能来自成本下降所创造的新需求。

### **3.3 Infra 将从服务模型走向服务 Agent**

目前 AI Infra 中相当一部分技术围绕模型的训练、部署和推理展开。但随着 Agent 逐渐成为智能的主要消费方式，基础设施所需要解决的问题也会发生变化。

一次模型调用通常具有相对明确的输入和输出，而一个 Agent 任务可能持续数小时，涉及多次模型调用、外部工具执行和复杂的状态变化。

如果未来一家企业同时运行大量 Agent，仅仅解决模型推理问题显然还不够。企业还需要管理任务生命周期、执行权限、计算资源以及任务之间的依赖关系。

由此可能形成一系列新的基础设施方向。

| 未来 Infra 方向        | 核心价值                     |
| ---------------------- | ---------------------------- |
| Model Gateway          | 统一模型接入、路由与成本管理 |
| Agent Runtime          | 管理任务执行、调度与异常恢复 |
| Memory Infrastructure  | 管理智能系统的长期记忆与经验 |
| Context Infrastructure | 动态提供和管理任务上下文     |
| Agent Sandbox          | 提供隔离、可控的任务执行环境 |
| Evaluation Platform    | 衡量任务质量并支持系统优化   |
| Agent Observability    | 追踪执行过程、定位失败原因   |
| Tool Infrastructure    | 管理外部工具、权限和调用协议 |

我们现在研究的许多 Agent 工程能力，未来可能逐渐从独立应用中抽离出来，成为标准化的公共基础设施。

就像传统软件发展过程中逐渐出现数据库、消息队列和服务治理平台一样，Agent 产业也可能形成属于自己的基础设施生态。

## **四、Agent 可能往哪里发展**

### **4.1 从辅助人类工作走向承担工作职责**

未来 Agent 最值得关注的变化，是它在人类生产活动中所承担的角色。

传统软件提供功能，用户通过操作软件完成工作。Copilot 进一步提高了个人工作效率，而 Agent 则开始承担更加完整的任务执行过程。

如果这一方向继续发展，未来 AI 产品可能经历以下几个阶段。

| 发展阶段   | 人类承担的工作       | AI 承担的工作    |
| ---------- | -------------------- | ---------------- |
| 传统软件   | 决策与操作           | 提供工具         |
| AI Copilot | 主导执行过程         | 辅助部分工作     |
| AI Agent   | 定义目标与验收结果   | 自主执行任务     |
| 自治系统   | 制定目标、监督与治理 | 持续承担业务职责 |

以软件开发为例，目前我们主要使用 AI 辅助编写代码、分析问题和生成测试。未来的 Coding Agent 可能长期负责某个项目模块的维护工作，包括处理缺陷、更新依赖和监控系统异常。

人类的工作重心也可能随之发生变化，逐渐向目标制定、业务决策、系统设计和质量监督转移。

当然，自治程度取决于任务风险和结果的可验证性。在金融、医疗等高风险场景中，人类授权与监督仍然可能长期存在。

### **4.2 从被动响应走向主动运行**

目前很多 Agent 仍然采用请求响应式的交互模式。用户提出一个任务，Agent 开始执行，任务完成后结束运行。

未来的 Agent 可能更多地以持续运行、事件驱动的方式存在。

例如，一个项目管理 Agent 可以长期连接代码仓库、需求平台和团队知识库。当新的需求出现时，它能够分析任务依赖；当项目进度发生变化时，它能够更新计划；当发现潜在交付风险时，它能够主动提醒相关人员。

用户不需要每天重新向 Agent 描述背景和下达指令。系统可以根据持久化的任务状态、历史经验和外部事件持续开展工作。

这一变化也会使 Agent 更接近传统软件中的长期运行服务，只不过它具备更强的环境理解与动态决策能力。

未来我们可能会从管理一个个 AI 对话，逐渐转向管理一组持续运行的智能系统。

### **4.3 从执行任务走向优化自身**

Agent 的进一步发展，可能体现在对自身执行机制的持续优化上。

目前 Agent 的 Prompt、工具链、上下文策略和 Harness 通常由开发者设计。当系统出现失败时，开发者需要分析日志、定位问题并手动调整。

未来，部分优化工作可能逐渐交给 Agent 自身。

例如，一个 Coding Agent 在长期运行过程中发现，自己经常因为缺少项目背景而产生错误修改。它可以根据历史执行记录定位问题，尝试调整上下文检索策略，并在独立测试环境中验证调整后的效果。

整个过程可以形成一个受控的优化闭环：

1. 收集任务执行记录和评测数据。
2. 分析失败原因，识别系统中的薄弱环节。
3. 生成针对 Prompt、工具链或上下文策略的优化方案。
4. 在独立环境中执行回归测试。
5. 比较优化前后的成功率、成本和执行效率。
6. 根据验证结果决定是否发布或回滚。

这里的关键在于建立可靠的评测机制。缺少验证和版本管理的自我修改，很容易将局部优化变成系统性退化。

如果未来这套机制逐渐成熟，Agent 的竞争可能从初始执行能力，延伸到持续学习和系统优化能力。

同样使用一个基础模型的两个 Agent，经过一年的运行之后，可能因为积累的业务经验和优化策略不同，形成截然不同的系统能力。

### **4.4 从单个智能体走向智能组织**

当 Agent 能够承担更加复杂的任务时，多个 Agent 之间的分工与协作也可能成为一个重要方向。

以企业研发为例，未来可能存在负责需求分析的 Agent、负责代码开发的 Agent，以及负责测试和审查的 Agent。它们通过共享任务状态、业务知识和验收标准完成协作。

但多 Agent 系统真正值得关注的地方，在于组织机制。

当多个具有自主决策能力的智能体共同参与任务时，如何划分职责、分配权限、解决冲突以及保证最终结果的一致性，都会成为新的工程问题。

这些问题与现实企业中的组织管理存在一定的相似性。企业需要制定流程、明确职责和建立监督机制，智能组织同样需要任务分工、通信协议和治理体系。

当然，多个 Agent 也会带来通信、推理和协调成本。因此，未来的智能组织需要根据任务复杂度决定采用单 Agent、多 Agent，还是确定性的传统工作流。

从更长远的角度看，Agent 开发可能逐渐演化为一种智能组织设计。开发者需要考虑如何组织多个智能能力，使它们以合理成本协同完成复杂目标。

## **五、未来 AI 产业的价值可能如何转移**

### **5.1 智能越丰富，组织智能的能力越重要**

技术发展往往伴随着稀缺资源的转移。

互联网降低了信息传播的成本，但优质内容、信息筛选和用户注意力仍然具有价值。云计算降低了计算资源的获取门槛，但系统架构和业务创新依然需要专业能力。

AI 也可能经历类似的变化。

当智能逐渐变得丰富，模型能力的获取成本不断降低，企业之间的竞争优势可能更多地来自如何使用这些智能资源。

我们在 AI Coding 中已经可以观察到类似的问题。个人编写代码的速度提高之后，团队整体交付效率未必同步提高，因为需求沟通、任务依赖、代码审查和系统集成仍然会影响最终结果。

如果所有团队都能够使用能力相近的 Coding Agent，那么团队之间的效率差距可能更多地体现在生产流程和组织方式上。

**当智能成为一种普遍资源，如何组织智能可能成为新的稀缺能力。**

### **5.2 从 Token 经济走向任务经济**

未来 AI 产业的商业模式，也可能随着智能系统的发展发生变化。

目前很多 AI 服务按照 Token、调用次数或者用户订阅周期收费，这些收费方式主要围绕智能资源的使用展开。

但对于企业而言，真正关心的是智能资源最终产生了多少业务价值。

假设有两个 Agent 系统，它们完成相同类型的业务任务，成本和成功率却有所不同。

| 评价指标          | Agent A | Agent B   |
| ----------------- | ------- | --------- |
| 单次执行成本      | 1 元    | 1.5 元    |
| 任务成功率        | 50%     | 95%       |
| 执行100次的总成本 | 100 元  | 150 元    |
| 预期成功任务数量  | 50 次   | 95 次     |
| 单位成功任务成本  | 2 元    | 约1.58 元 |

在这个假设案例中，Agent B 虽然单次执行成本更高，但完成一个有效任务的平均成本反而更低。如果再考虑失败返工和人工审核，两者的实际成本还可能存在更大差异。

因此，未来评价一个 Agent 系统的经济价值，可能需要综合考虑任务成功率、执行成本、人工介入程度和最终交付质量。

从商业模式来看，AI 产品也可能逐渐从出售智能资源，延伸到出售任务执行能力。对于验收标准清晰的业务，按照成功任务数量或者交付结果收费，可能成为更值得探索的商业模式。

**单位有效任务成本，可能成为未来 AI 产业的重要竞争指标。**

### **5.3 今天的应用创新可能成为明天的基础设施**

基模、Infra 和 Agent 之间的价值边界会持续变化。

今天，一个 Agent 开发团队可能需要自行实现任务调度、长期记忆、上下文管理和工具权限控制。随着越来越多的团队遇到相似的问题，这些能力可能逐渐被抽象为独立的基础设施。

同样，今天部分依赖复杂 Agent 工作流实现的功能，未来也可能被基础模型直接吸收。

由此可见，未来 AI 产业可能持续出现两种能力迁移。

| 能力迁移方向        | 形成原因             | 可能产生的结果           |
| ------------------- | -------------------- | ------------------------ |
| Agent 向基模迁移    | 模型原生能力增强     | 部分应用工程机制被简化   |
| Agent 向 Infra 迁移 | 多个应用出现共性需求 | 通用能力被标准化和平台化 |

这会不断降低 AI 应用的开发门槛，同时也可能压缩部分应用产品的利润空间。

对于开发者而言，值得积累的是那些能够随着模型进步而持续增值的能力，而非长期依赖某一代模型的能力缺陷。

对于企业而言，则需要不断判断哪些能力应该自行研发，哪些能力可以交给成熟的基础设施，以及哪些业务能力值得长期保留在自身系统中。

### **5.4 创造价值与获取价值可能进一步分离**

虽然基模、Infra 和 Agent 可以概括 AI 产业的主要技术价值来源，但最终的商业价值分配还涉及其他因素。

一家企业可能没有自研模型，也没有自主构建推理基础设施，却拥有大量高质量行业数据、成熟的业务流程和稳定的客户资源。这些资源能够帮助企业将通用智能转化为具有行业竞争力的产品。

因此，未来 AI 产业的竞争可能同时存在技术供给侧和业务需求侧两条主线。

技术供给侧围绕模型能力、基础设施和任务执行效率展开；业务需求侧则围绕数据、用户入口、行业知识和业务流程展开。

技术创新决定了能够创造多少新的价值，而企业掌握的业务资源，则可能影响这些价值最终由谁获取。

这也意味着，未来即使基础模型能力逐渐趋同，AI 应用层仍然可能存在大量商业机会。不同企业在业务理解、数据积累和组织效率上的差异，不会因为使用相同的模型而自动消失。

## **写在最后**

如果将时间拉长到未来五年甚至十年，AI 产业可能会形成一套更加完整的智能工业体系。

基础模型负责不断生产更强大的智能，Infra 负责以更低的成本、更高的效率供给智能，Agent 则负责组织智能，将其转化为现实世界中的生产活动。

三个方向之间会形成相互促进的产业循环。模型的进步创造新的应用机会，基础设施的成熟降低应用成本，应用的发展又会产生新的模型需求和基础设施需求。

在这个过程中，产业的价值重心也可能不断发生变化。

当智能能力不足时，价值更多地集中在模型突破；当智能能力提高但成本过高时，Infra 的重要性进一步凸显；当智能既强大又便宜时，如何将智能组织成可靠的生产系统，可能成为新的竞争焦点。

当然，基模、Infra 和 Agent 并非三个相互替代的发展阶段。即使未来 Agent 已经能够承担大量生产活动，底层模型和基础设施仍然需要持续发展。

我们现在所研究的 Prompt、RAG、MCP、Skill、Memory 和 Harness Engineering，或许只是这套智能工业体系逐渐成形的早期探索。未来具体的技术名称可能发生变化，但智能如何被创造、如何被供给、如何被转化为生产力，这三个问题仍然值得长期研究。

**AI 产业的起点是创造智能，而它的长期价值，可能在于围绕智能重新构建整个社会的生产方式。**
